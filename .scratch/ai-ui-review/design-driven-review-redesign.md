日期：2026-09-15

状态：主链路已按 TDD 改造并完成回归；首个真实案例尚未全部验收通过，具体缺口见第 9 节。

来源：本轮 grill-me 讨论，以及用户对“美联储观察”报告的人工反馈。

本文描述目标行为，不代表当前代码已经实现。继续遵守 `CONTEXT.md`、ADR 0002 与 `docs/DESIGN_COVERAGE.md` 的证据边界。现有文档中的历史交集忽略策略不能覆盖本规格。

已实现范围与尚未满足的真实案例要求分别记录在第 9 节，不能从回归测试通过推断全部目标已实现。

## 1. 目标

以 DesignTruth 为主线，先建立完整审查清单，再寻找 ActualEvidence 对应关系。报告覆盖通过、差异和待核验内容，让人工能够顺着设计核对，也能快速定位问题。

系统应识别并解释结构缺失，让其他正常区域继续独立验收；对动态内容按字段用途与属性依赖审查，避免数据变化制造视觉误报。

问题数减少、相似度提高或待核验增加，都不能单独证明识别质量改善。

## 2. 双向覆盖与可变层级

- 每个非根设计节点必须有去向，不受匹配或 Agent 候选预算限制。
- 实际页面没有设计对应的可见内容也进入报告。按可见区域聚合；纯 DOM 包装层不逐个视为额外内容。
- 未匹配是对应关系待核验，不能直接等同于缺失或多余。
- 审查结构采用可变深度区域树，不强制“模块—结构—元素”三层。
- Figma 分组合理时沿用；视觉边界明确时，可依据背景、包含关系和间距构建独立审查分组，始终保留原始 Figma ID、父 ID 和类型。
- 无法可靠分组时保留独立设计项，在最近可信区域内查找；仍无对应则展示设计裁图、位置和待核验原因。
- 分组置信度与对应关系置信度分开。不确定分组归属，不应阻止明确 ID、唯一文字等独立证据形成对应。
- 子项归入父问题时仍保留清单记录与链接，不把“由父问题覆盖”写成通过。

## 3. 区域对应与局部比较

- 先建立可信区域对应，再在区域内匹配元素；未找到父区域时允许受约束的逐项兜底。
- 单个区域缺失、歧义或 Agent 失败不能阻断其他独立区域的比较。
- 无法建立可靠对应的区域继续待核验，不能为提高匹配数量而跨区域强配。
- 可靠匹配区域可以使用局部坐标比较内部布局，同时保留设计与实际的原始绝对坐标。
- 对应关系本身不代表通过；必须有实际执行的检查结果。

### 3.1 缺失与连带位移

若 A 缺失，B、C 因此共同上移：

1. 发布有证据支持的 A 缺失问题。
2. 记录 A 对 B、C 的影响，包括缺失区域、受影响区域、原始位置、测得位移和验证依据。
3. 扣除已验证共同平移后，检查 B、C 内部位置、样式和像素。
4. 不再把该共同平移重复发布为每个子元素的位置错误或像素失败。
5. B、C 内部真实差异、异常模块间距仍独立报告。

多处缺失时，应表达具体的因果链与累计影响。必须核验顺序、几何、稳定锚点和残差，不能把历史报告中的偏移量直接分配给某个缺失模块。

只允许有证据的补偿，不能通过任意缩放、移动消除真实缺陷。原因不明时保留区域位置待核验。

全页原始差异图继续作为诊断证据；验收相似度基于对齐后的可审查区域，另记录审查范围、豁免范围及覆盖缺口。无可审查证据不能表现为整页通过。

## 4. 动态字段按用途与属性审查

### 4.1 文本

- 已确认动态用途后，即使采样期间没有变化，也可豁免具体文案。
- 日期、时间、概率、表格数值、列表内容、动态状态值按各自用途处理。
- 固定标题、字段标签和按钮固定文案继续检查内容。
- 已验证的动态文本豁免不解除字体、对齐、间距、容器和溢出检查。
- 用途不明确时，把文本豁免决策列为待核验；可确认的样式继续检查。

### 4.2 文字尺寸与排版

- 动态字符长度导致的自然文字包围盒变化，不单独报告尺寸问题。
- 容器宽度、内边距、对齐锚点、字号、行高继续检查。
- 单行、多行、最大行数及省略方式依照可确认的设计约束检查。
- 遮挡、溢出、破坏列对齐等仍应报告。
- 设计允许的伸缩方式不明确时待核验，不擅自接受所有重排。

### 4.3 列表与固定槽位

- 已确认的数据驱动列表允许条数和排序变化，以设计行或卡片模板检查每个实际条目。
- 合法新增数据行不作为额外模块；每个条目仍应有检查去向。
- 行数合法变化引起的后续区域移动，可走经过验证的布局影响路径。
- 固定业务槽位不能当作动态数据行豁免。例如“最新概率／上一日概率／上周概率”的表头、顺序和完整性仍须检查。
- 空列表需要有效的空状态依据，否则列为待核验。

### 4.4 状态样式

- 有设计支持的状态或 MarketVariant 时，按对应状态检查颜色、图标及其他属性。
- 缺少对应状态设计时，继续检查能确定不随状态变化的属性。
- 可能随状态变化但缺少设计依据的属性明确待核验，不能套用另一个状态，也不能由 AI 发明允许的样式。

### 4.5 数据驱动的视觉属性

- 动态豁免可以覆盖有明确数据依赖的视觉属性，例如概率条长度。
- 必须记录具体节点、属性、数据依赖及支持证据，不能扩大为整块区域豁免。
- 概率条长度合法变化时，仍检查轨道尺寸、条形高度、颜色、位置和对齐等不变约束。
- 只有文本值不同或 AI 自称动态，不足以豁免几何属性。
- 是否进一步验证“实际数值与图形比例一致”不属于本轮已确认的新增要求；不得据此宣称已验证业务数据正确性。

## 5. AI 参与边界

- 明确用途由规则处理；有歧义的字段可按区域调用 AI 分类。
- 输入包括设计和实际局部证据、层级与邻近标题；输出必须包含具体节点、字段用途和判断依据。
- AI 分类后由独立规则审核对应关系、上下文及支持的类型。
- AI 不能单独决定文本或视觉属性豁免，不能因文字不同就忽略，也不能把父卡片中的固定标题连带豁免。
- 仅有模型判断、缺少佐证时保留待核验，继续可执行的样式检查。
- AI 对匹配和分组的提案仍受现有确定性验证边界约束。
- 保留各项豁免、拒绝与降级的来源和依据；AI 汇总仍只引用允许的发布证据。

## 6. 报告与验收状态

### 6.1 主视图

报告主视图采用设计走查清单，按设计空间顺序及可变层级展示，问题汇总和筛选作为快捷入口。

每个应审项至少应提供：

- 原始设计身份、所属审查区域及实际对应身份；
- 设计／实际裁图或可访问的证据引用；实际不存在时明确展示缺失，不能制造实际框；
- 对应关系状态与审查结果，二者分开；
- 每项已执行检查的设计值、实际值、适用容差、结果和证据；
- 通过、差异、待核验的明确区分；
- 动态豁免、不适用、未执行的独立标记及原因；
- 关联问题、根因及位移影响链；
- 无设计对应的实际可见内容进入补充清单。

“没有产生问题”“matched”“被父项覆盖”均不能直接转换成检查通过。动态豁免不能写成文本或几何检查通过。

### 6.2 统一验收结论

| 条件 | 验收结论 |
| --- | --- |
| 存在已确认的阻断问题 | failed／未通过 |
| 无阻断问题，但仍有应审内容未核验 | needs_review／待复核 |
| 应审内容完成检查，无阻断问题 | passed／通过 |

执行状态与验收结论保持分离。AI 汇总失败本身不影响验收；匹配失败留下的应审覆盖缺口会影响验收。

Web、单页、批量、公共 API、MCP 与导出产物采用同一标准。公共 JSON 继续使用证据引用，不能塞入大块图片字节。

## 7. 首个验收案例：美联储观察

### 7.1 用户确认的预期

设计来源：美联储观察，Figma Frame `0:72`。

用户明确指出“快评、最新货币政策、投票”为整体缺失模块。该反馈是本页人工预期，不等同于系统已取得可发布的自动缺失证据，不得硬编码这些名称来使测试通过。

| 检查对象 | 验收预期 |
| --- | --- |
| 快评、最新货币政策、投票 | 分别形成清晰的设计区域标注、缺失结论及支持证据；不只留下通用组名与含糊提示 |
| 缺失后的正常区域 | 一一正确对应，说明受到哪些缺失区域影响及测得位移；局部真实差异仍可检出 |
| 日期与会议时间值 | 具体值可豁免；字体、间距、对齐与选中／未选中状态按可用设计依据检查 |
| 利率区间与百分比数值 | 具体数据可豁免；列对应、数字排版、行列对齐继续检查 |
| 概率表头 | “概率／最新概率／上一日概率／上周概率”等固定标签按对应位置检查文字与样式 |
| 概率条 | 确认数据依赖后豁免长度差；轨道、条高、颜色和对齐仍检查 |
| 热点解读 | 固定模块标题正常检查；动态新闻内容按卡片模板检查排版、间距与溢出 |
| 已通过项 | 清单中可见并可展开检查值、对应裁图和依据，方便人工发现漏报或错误匹配 |

### 7.2 当前报告的观察基线

本轮查看的报告显示：已匹配 33 个元素、设计未匹配 225 个、实际未匹配 113 个、动态区域 0 个；包含约 375px、650px 的集中位置偏移。该报告另显示 Agent 结构审查失败。

这些是旧报告中的观测，不是算法质量指标；不能直接证明具体位移由哪些模块缺失引起，也不能当作改造后的目标数值。

### 7.3 验证要求

- 重新获取与用户反馈相符的原始 DesignTruth 和 ActualEvidence，保留运行版本与规则。目标页面状态如有变化，应明确区别。
- 用户上传的三张局部图只能说明局部检查需求，不能代替完整页面采集与缺失证明。
- 验证缺失与独立区域对应，并同时保留已知真实样式错误的检出能力。
- 回归应包含：单个与多个前序缺失、错误跨区域匹配、无法分组、动态值未变化、动态文字自然尺寸变化、可变行数、固定槽位缺失、未知状态、概率条长度变化、AI 失败及没有可审查证据。
- 验证同一根因不再重复触发后续元素位置和像素失败，且真实局部偏移没有被补偿掉。
- 检查所有应审项均有去向，且通过、豁免、待核验、未执行没有混淆。
- 核对报告、JSON、HTML、Markdown、Excel 与公共结果的一致性。
- 当前人工反馈与附件不是已获复用授权的校准金标；继续遵守设计师批准、数据脱敏／公开和显式复用授权的导出门禁。

## 8. 实现落点与顺序

以下是实施建议，具体类型和字段名需在实现时核对，不能当作已发布 API。

1. **审查结果模型**：在 `src/types.ts` 明确区分对应关系、逐属性检查、动态豁免、证据不足和区域影响，避免从 ReviewIssue 的缺席反推通过。
2. **设计区域与双向清单**：将完整审查清单前置，扩展 `design-coverage.ts` 与独立区域视图；保留原始 DesignTruth，支持可变深度及无分组兜底。
3. **区域对应与位移因果**：在比较链路建立可验证的区域身份及局部坐标，扩展 `compare.ts`、`review-issue.ts` 的影响证据；把补偿用于局部比较，而非仅在报告阶段合并重复问题。
4. **属性级动态策略**：扩展 `dynamic.ts`、`normalization-plan.ts`、`market-list.ts` 与 `market-variant.ts`，分别控制文本、自然文字尺寸、状态和数据驱动几何；保留不变属性检查。
5. **全量报告与统一结论**：让 `report.ts`、`excel-report.ts` 与 Web 视图消费同一逐项审查结果，统一 needs_review；检查公开契约兼容性。
6. **真实案例验收**：重新运行本页，按第 7 节人工预期逐项核对；进一步扩大金标后才能评估真实精确率、召回率、待核验占比及一致性。

编排继续位于 `server/review.ts`。HTTP 与 MCP 保持适配层；保留租户隔离、并发与队列、签名、凭据、长图绝对坐标及制品边界。

## 9. 本轮实现与验证（2026-09-15）

- 已实现独立可变深度审查树、完整设计清单和实际侧补充清单；每个属性记录通过、差异、待核验、动态豁免、不适用或未执行。
- 可信区域对应约束元素匹配；独立区域采用平移后的局部位置与像素比较，保留原始截图和绝对坐标，不进行缩放补偿。
- 新增静态标签和经验证布局间隙的缺失证据。因果链按独立间隙去重累计，部分解释保留剩余位移待核验；已知局部缺陷不并入整体位移。
- 已验证日期／概率字段可在值未变化时免比较具体内容；自然文字宽度、未知伸缩约束、目标状态缺证据分别处理。概率条仅在明确的百分比宽度依赖得到采样佐证后豁免宽度。
- 已确认列表的每条实际行保留独立属性检查；数据文字像素豁免不解除行装饰、字体、列结构或溢出检查。
- Web 主清单与 JSON、Markdown、HTML、XLSX 同源；缺失项不制造实际裁图；统一 `failed / needs_review / passed`，无证据不能通过。
- TDD 增量回归后，完整测试 360/360 通过，`npm run build` 通过。浏览器检查了分层清单、缺失裁图、通过项筛选及横向溢出。

### 真实案例回放

使用本轮取得的原始 Figma 与三次 Live 采样离线重放，关闭 AI，便于复现确定性边界。产物在 `outputs/design-review-redesign/`；不是线上最新数据保证，也不是获准复用的校准集。

- 315 个设计项均进入清单，记录 476 条属性检查，最终结论 `failed`。
- 确认“最新货币政策”和“投票”缺失；“快评”仍为待核验，缺少可独立发布的静态／布局证据。
- 利率观察、相关品种动态、热点解读有独立区域对应。约 650px 上移中，约 276px 得到投票缺失间隙支持，其余约 374px 仍待核验，未整体归因给投票。
- 日期选择区有设计 5 槽与实际可见 4 槽以及内部滚动限制，未强行按序对应。动态新闻的设计拆行与实际合并文本、其他未确定的表格单元格仍保留覆盖缺口。
- 原采样未采集新增加的声明式百分比宽度证据，不能据此回放认定该页概率条已通过豁免；新采集链路已由浏览器用例验证。

首个案例尚未满足第 7 节全部人工预期。后续需补充局部滚动与文本片段对应证据，完成快评及动态表格／新闻核验；不能仅放宽匹配阈值。真实精确率和召回率尚未测量。
