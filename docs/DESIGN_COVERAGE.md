# 设计驱动的逐项走查

当前默认策略取代旧“只比交集、未匹配忽略”的规则。HTTP、MCP 和网页仍复用同一个比较链路，无新接口或开关。

## 输出契约

Review JSON 的 `matching.designCoverage` 包含：

- `policy: design-driven`。
- `captureSamples`：采样编号与完整性元数据，不包含图片字节。
- `items`：全部非根 DesignTruth 节点，不受元素匹配/Agent 候选数量上限影响。
- 每项保留 `figmaNodeId`、`parentFigmaNodeId`、名称、设计坐标、`status`、`reasonCode`、实际 `selector` 和最终 `issueIds`。
- 子项合并时，`coveredBy` 指向负责该子树的最终问题 ID，不表示子项已通过。
- 静态缺失的 `absenceEvidence` 记录用于判断的静态标识文本与采样编号。

| status | 含义 |
| --- | --- |
| matched | 已取得对应关系；是否存在样式差异仍以 ReviewIssue 为准，不等于验收通过 |
| missing | 已发布缺失问题 |
| unverified | 无法确认对应关系或实际采集不足，产生 pending 问题 |
| covered-by-parent | 由父区域问题统一处理，保留逐项记录 |
| structural-only | 无独立样式的包装组存在已绑定子项；只说明结构关系，不代表全部子项通过 |

网页与 HTML 的清单默认折叠；Markdown 使用表格；XLSX 增加“设计覆盖清单”工作表。缺失和未验证问题沿用现有问题表、截图标注与导出链路。

## 静态缺失证据（当前实现）

新增确定性路径要求 Live 至少三次完整文档采集，且无元素采集上限截断、不透明内容或排除区域。一个尚无已绑定子元素的区域，至少有两个非数值、非动态且长度为 4–32 字符的静态标识，在所有采样文本中都不存在相等/包含对应关系，才发布 `missing_module`。记录标识和采样编号供复核；无需 Agent 提案和位移 residual。

这是保守的文本/DOM 证据路径，不是通用视觉缺失识别器。少于两个标识、短标签、可能的动态文案、已有部分对应证据、图像内文字、复杂截图或不完整采集等情况继续明确标为未验证，不能宣称已排除所有可能对应关系。未知动态文案仍可能需要进一步分类与人工核查；标签规则需要真实样本验证，不能据此声称真实页面准确率已提升。

原先 Agent 验证加稳定兄弟位移的路径仍保留，已发布问题会复用，避免重复发布；其 residual/overlap 校准并不控制新增静态路径。

## 动态与范围边界

- 已验证动态节点，以及明确的新闻、列表、日期、轮播等动态上下文，不以文案变化作为静态缺失依据。
- 已绑定动态元素仍进入已有字体、颜色、边框等检查。模板绑定也进入覆盖清单。
- 裁切截图、Hybrid 与长截图分片不因为 DOM 补充证据存在就被当作完整 Live 文档；新静态缺失路径不会越过上传图像的视觉真值边界。
- `design_coverage_unverified` 为 pending，不生成“恢复模块”的确定性建议。静态缺失为 error；动态和未验证项不会静默消失。
- 旧报告没有采集完整性元数据，必须重新走查，不能刷新旧 JSON 后推断缺失。

## AI 汇总

静态缺失一旦成为最终 ReviewIssue，即进入强制汇总覆盖。Agent 只排序已有证据，不能抹掉这些缺失问题，也不能凭自由文本编造缺失。未验证项同样作为正式 pending 问题供汇总引用，但不得改写成确定缺失。

## 模块核验修正（2026-09-14）

- 覆盖审查使用独立的模块视图，不改写用于匹配的 DesignTruth。宽度达到 Frame 的 70%、高度至少 60px 的平级矩形背景，可收纳几何完整包含的同级节点；多个背景均可包含时不猜测归属。输出仍保留真实 Figma ID 和原父 ID。
- 有子节点、满足上述宽高且高度小于 Frame 80% 的区域可输出 `ReviewIssue.coverageModule: {id,name,nodeIds}`。待核验模块集中展示，子项链接同一问题；有独立匹配的元素仍保留自身样式问题。名称优先使用上方非数值文本，不能保证图像内“快评”等标题一定可读。
- `captureSamples[].coverage` 在发现局部裁剪时增加 `documentBoundsComplete` 和 `limitations[{reason,selector,box}]`。坐标为实际文档坐标。仅当文档边界完整、所有受限项均为无子元素的文本裁剪且宽高都小于待检区域时，该区域允许继续静态缺失检查。内部滚动容器、缺少范围元数据、不透明内容、采集截断、排除区域仍阻断确定性缺失。局部裁剪不会自动等价于整页不可审查。
- 结构几何/Agent 视觉候选不能直接作为覆盖已验证身份。确定性 ID、稳定文本、经验证模板对应可作为存在证据；截图独立视觉锚点的唯一同文绑定保留。原候选及样式问题不会被删除。
- 所有带 `coverageModule` 的 pending 覆盖问题强制进入成功生成的 AI 汇总，且保留待核验措辞。网页、HTML、Markdown 不依赖 AI 成功即可展示模块核验建议；XLSX 使用相同最终问题表。未知不自动升级为缺失，也不会被省略。
- 这些是保守的几何分组与覆盖规则，不包含对任意动态模块的自动语义证明。真实案例须重新采集验证；历史 Review JSON 缺少原始 Figma/DOM 证据，不能作为完整端到端重放输入。

### 局部范围与超时降级补充

- VECTOR 卡片同样参与覆盖模块聚合，采用矩形背景相同的同级完整包含、宽度至少 Frame 70%、高度至少 60px 条件，另排除高度达到 Frame 80% 的页面级矢量背景。多个候选背景重叠时仍不猜测归属。此处只利用包围盒构建覆盖视图，不证明矢量路径是矩形，也不证明实际页面存在或缺失。保留原始 VECTOR 类型、Figma ID 和父 ID；完整采集门禁不变。回归包含真实政策卡片的最小类型/几何复现，不代表重新执行完整线上走查；旧报告需要重跑才会更新模块聚合。

- 局部限制若位于已有可信绑定的 FRAME/GROUP/COMPONENT/INSTANCE 实际容器内，只阻断相关设计子树；不阻断与该子树无祖先/后代关系的设计区域。仅文字锚点、几何候选、根 Frame 或未知归属不能提供此豁免。`fullDocument` 保持原始值，不强行改为完整。
- 覆盖条目增加 `nodeType`、`originalName`、`groupedParentFigmaNodeId`，便于区分原始 Figma 类型、原始父子关系和覆盖分组关系。这些信息不是完整 DesignTruth 快照，不能代替原始采集重放。
- 通用组名优先使用首行靠左的短标签，容忍同一行字体基线差异；无法读取的图像标题仍不会凭空命名。
- AI 汇总每批最多 64 条证据，串行共享 60 秒总请求预算；格式修复也受该预算约束。后续批次失败时，可发布已完成批次的部分排序，同时保留 `aiAdviceRejection`。未排序的强制缺失/模块待核验问题仍通过确定性覆盖加入建议。部分成功不是完整成功，也不改变验收结论。此分批仅适用于汇总排序，不改变元素绑定 Agent 的两轮机制。

## 逐项审查与局部比较（2026-09-15）

本节更新此前“折叠辅助清单”与分组阈值的描述，目标规格及真实案例缺口见 `.scratch/ai-ui-review/design-driven-review-redesign.md` 第 9 节。

- Web 主视图采用可变深度设计清单。分组视图与对应关系共用可追溯区域身份，保留原始 Figma ID／父 ID／类型。矩形或矢量背景高度至少 40px，宽度达父区 70% 或完整包含至少两个同级项；唯一内层容器优先，重叠歧义退回唯一共同容器或独立项。几何分组本身仍不证明对应关系。
- `items[].checks` 保留每条实际模板实例的逐属性 expected／actual／tolerance／status／reason／selector／actualBox；`reviewStatus` 与对应关系 `status` 分离。`actualItems` 记录无可靠设计对应的可见实际内容，未匹配不等同于额外缺陷。
- 至少两个独立静态锚点的跨样本稳定证据可以形成 `verified-region` 对应。可信外层边界阻止跨模块错配，内部 Figma／DOM 嵌套不同时不要求机械同构。已验证区域仅平移参与局部测量，原始坐标与原始像素差异图保留。
- 除原多标签静态路径外，可由前后独立区域、稳定短标题缺席、完整相关采集和移除高度／间隙残差建立缺失证据。`absenceEvidence.layoutGap` 记录完整缺失链、影响区域与残差。长免责声明中的同字片段不冒充标题对应；动态内容仍不证明缺失。
- `items[].displacement` 记录总位移、已解释量、待核验余量与根因 ID。部分缺失只能解释相应增量，不能隐藏剩余位移或区域内真实缺陷。
- 明确日期、概率等用途可在三个样本数值不变时归一化，前提是可靠字段对应与独立稳定证据。固定文本前缀继续比较。未知文字伸缩、缺少目标状态设计保留待核验；已验证列表文字像素豁免不解除逐行样式／结构审查。
- `dynamicNormalization.geometry` 记录概率条宽度依赖的条、轨道、数值身份及采样证据。仅当声明式百分比宽度、实际几何和字段值一致时豁免宽度，保留高度／颜色／位置检查；不代表业务数据正确。
- `matching.visualScope` 记录 reviewed／changed／excluded／canvas 像素数。相似度只描述可审查部分，无证据或存在应审覆盖缺口不能判通过。
- HTML／Markdown／XLSX 输出同一清单和检查记录，XLSX 有逐属性、实际侧与审查范围工作表。明确缺失项没有伪造的实际裁图。统一验收规则为阻断问题 failed、未完成核验 needs_review、否则 passed；执行状态继续独立。

真实案例已确认政策、投票缺失，快评、部分滚动日期和扁平新闻字段仍待核验。测试覆盖边界行为，不能代替真实精确率／召回率测量。

### 报告一致性修复（2026-09-15）

- 逐属性 X/Y 各自以坐标差判定；整体位置问题仍可使用二维距离，不能把 X 超差写成 Y 超差。
- 新 Live 采集通过 DOM Range 与布局框区分承载文字的容器，记录 `textInLayoutContainer`。当 Figma TEXT 对应这种容器时，位置、尺寸和行高缺少独立文字布局证据，标为 pending，并停止用容器尺寸发布文字几何／行高错误。字号、字体、字重、文案等独立检查保留。此修复不宣称已完成文字边界测量；必须重新采集，旧报告不会自动修正。
- 清单审查结果在最终问题聚合后与本项正式问题对齐：本项有 error／warning 时为 difference，有 pending 时不能标 passed。已通过的属性记录不受影响，关联父根因不会无差别改写子项结果。
- 三项故障均先复现失败，再修改实现；完整回归 362/362 通过，生产构建通过。

### 波段决策案例第一版修复（2026-09-15）

- 叶级矢量／线条等图形不能绑定有可见文案的实际价格标签。Live 几何／视觉推测仍可保留候选与逐项待核验，但不生成针对未经验证对象的 CSS 整改问题；截图 OCR 原有受限参数审查保持独立。
- 独立区域识别不再因最近公共容器已被占用而跳到其父容器；设计子区域不能映射到已对应实际父区域的祖先。区域绑定置信度不得高于区域证据评分，避免低可信边界产生高可信尺寸结论。
- Live 采集保存 `expanded` 与 `expansionEvidence`。支持 `aria-expanded`，以及明确“展开”控件和附近兄弟内容实际发生裁切的联合证据。三个样本持续折叠、候选设计区域比实际区域更高时，相关高度／下游纵向位置保留待核验，横向偏差继续测量。候选关联不能证明因果关系；不自动点击、不宣称位移已补偿。
- `visuallyObscured` 记录当前元素或祖先的非零 CSS blur。被模糊文字的检查保留 pending，不把 DOM 隐藏字体属性直接发布为可见视觉缺陷。该检测不覆盖所有透明遮罩、canvas 或业务权限机制。
- 数字表格增加结构识别：唯一静态表头、至少两个数字字段、列数量及列几何对应，可替代特殊 Figma 命名。实际侧仍需独立容器对应与重复结构证据；不能依靠几何单独认证，也不自动覆盖任意复杂嵌套表格。
- 本版通过合成回归验证修复边界；真实 H5 重新采集确认了模糊数据。未经完整 Figma/Live 比对重跑，不能把旧 Excel 当成新算法结果，也不能宣称该案例已全部验收通过。
